Section 3 — Phase 1: File Handling (Week 10)

In this phase, you will convert structured data between CSV text and associative PHP arrays. The key idea is that files are sequential streams, so you must manage modes, headers, row order, and error handling intentionally.

Learning objectives

  • Use fopen(), fgetcsv(), and fputcsv() correctly.
  • Choose the correct file mode for overwriting versus appending.
  • Transform CSV rows into associative arrays using a header row.
  • Handle missing files and empty files gracefully.

Required method signatures

public function writeRecord(string $filePath, array $record): bool
public function readAllRecords(string $filePath): array
public function appendRecord(string $filePath, array $record): bool
Method Input Output Contract
writeRecord() Path + one associative record bool Create or overwrite a CSV file, write the header row, then write exactly one data row.
readAllRecords() Path to CSV file array Return all rows as associative arrays using the first row as the header definition.
appendRecord() Path + one associative record bool Add a new row at the end of the CSV file and write headers first if the file is new or empty.

CSV format specification

The CSV file stores student records with the following columns:

name: string reg_no: string age: integer-like string email: string mark1 to mark4: numeric strings

Constraint: preserve header order. If the header row is name,reg_no,age,email,mark1,mark2,mark3,mark4, then every row must follow that exact order.
Worked example: CSV input to PHP array output 
# CSV file contents
name,reg_no,age,email,mark1,mark2,mark3,mark4
Grace Wanjiku,EN271-0001-2022,21,grace@example.com,78,82,80,75
Brian Otieno,EN271-0002-2022,22,brian@example.com,65,71,69,73
# Expected PHP array shape
[
    [
        'name' => 'Grace Wanjiku',
        'reg_no' => 'EN271-0001-2022',
        'age' => '21',
        'email' => 'grace@example.com',
        'mark1' => '78',
        'mark2' => '82',
        'mark3' => '80',
        'mark4' => '75'
    ],
    [
        'name' => 'Brian Otieno',
        'reg_no' => 'EN271-0002-2022',
        'age' => '22',
        'email' => 'brian@example.com',
        'mark1' => '65',
        'mark2' => '71',
        'mark3' => '69',
        'mark4' => '73'
    ]
]

Common mistakes to avoid

  • Using explode(',') instead of fgetcsv(), which breaks on quoted values.
  • Forgetting to close file handles.
  • Using mode 'w' when you meant to append with 'a'.
  • Returning indexed rows instead of associative arrays.

Section 4 — Phase 2: Search & Sort (Week 11)

This phase develops your algorithmic thinking. You will not only produce correct outputs, but also report iteration counts so you can compare how different sorting strategies behave on the same data.

Learning objectives

  • Understand the difference between linear and binary search.
  • Implement bubble sort, selection sort, and insertion sort correctly.
  • Build intuition for Big-O complexity using best, average, and worst cases.
  • Relate nearly-sorted input to iteration count behavior.

Required method signatures

public function linearSearch(array $items, int|string $target): int
public function binarySearch(array $items, int|string $target): int
public function bubbleSort(array $items): array
public function selectionSort(array $items): array
public function insertionSort(array $items): array
Algorithm Input Output Return type
Linear Search Indexed array + target Index of target or -1 int
Binary Search Ascending sorted array + target Index of target or -1 int
Bubble Sort Indexed array Sorted array + iteration count array
Selection Sort Indexed array Sorted array + iteration count array
Insertion Sort Indexed array Sorted array + iteration count array
Algorithm Best Case Average Case Worst Case
Linear Search O(1) O(n) O(n)
Binary Search O(1) O(log n) O(log n)
Bubble Sort O(n) with optimization or O(n²) in naive form O(n²) O(n²)
Selection Sort O(n²) O(n²) O(n²)
Insertion Sort O(n) O(n²) O(n²)
Iteration count contract: each sort method must return ['sorted' => [...], 'iterations' => 0]. The autograder uses both the sorted output and the numeric iteration count.
Trace table example: bubble sort on [5, 3, 1, 4, 2]
Pass 1 Start: [5, 3, 1, 4, 2] End: [3, 1, 4, 2, 5]
Pass 2 Start: [3, 1, 4, 2, 5] End: [1, 3, 2, 4, 5]
Pass 3 Start: [1, 3, 2, 4, 5] End: [1, 2, 3, 4, 5]
Pass 4 Start: [1, 2, 3, 4, 5] End: [1, 2, 3, 4, 5]

Nearly-sorted data insight

Insertion sort usually performs fewer shifts and comparisons than bubble sort on nearly-sorted input. That is why one of the tests compares iteration counts on a nearly-sorted array.

  • Correct iteration tracking: 1 mark

Learning objectives

  • Differentiate between GET and POST in a practical form workflow.
  • Validate user input on the server, not just in HTML.
  • Separate view code from reusable validation methods.
  • Escape rendered values to avoid accidental HTML injection.

Section 6 — Phase 4: Error Handling & Debugging (Week 13)

This phase teaches defensive programming. Instead of letting PHP fail unpredictably, your code should detect unsafe situations early and raise clear exceptions that make debugging easier.

Learning objectives

  • Differentiate file errors from logical errors like division by zero.
  • Use try, catch, and finally clearly.
  • Throw meaningful exceptions instead of hiding failures.
  • Understand how better error messages reduce debugging time.

What you must implement

public function safeReadFile(string $filePath): string
public function safeWriteFile(string $filePath, string $content): int
public function safeDivide(int|float $dividend, int|float $divisor): float

Exception hierarchy idea

Exception

Base throwable type used for controlled application failures.

RuntimeException

Suitable for missing files, unreadable files, unwritable paths, and rejected zero divisors in this mini-project.

try-catch-finally example with annotations 
try {
    // Attempt a risky action
    $contents = $handler->safeReadFile('students.csv');
    echo $contents;
} catch (\RuntimeException $e) {
    // Explain the failure clearly
    echo 'Error: ' . $e->getMessage();
} finally {
    // Useful for cleanup or logging
    echo 'Operation finished.';
}

Common PHP error categories

Syntax errors

These happen before your script runs, for example a missing semicolon or unmatched brace.

Runtime errors

These happen while the script is running, such as trying to open a missing file.

Logical errors

The script runs, but the result is wrong because the algorithm or conditions are incorrect.

Fatal errors

These stop execution entirely, often due to severe problems like calling undefined functions.

Error handling is not about hiding mistakes. It is about failing clearly and safely so the problem can be fixed quickly.
